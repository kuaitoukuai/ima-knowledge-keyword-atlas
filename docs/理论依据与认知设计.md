# 理论依据与认知设计

> 这份文档回答一个问题：**为什么这套流水线要长成这样？**
>
> 它不是"我们试了觉得还行"，而是对应着认知科学、结构化思维与信息检索三方面的既有研究成果。
> 同时说明本项目**采用了哪些、没采用哪些、下一步可以引入哪些**。

---

## 一、问题的本质：瓶颈已经从「生产」转移到「吸收」

### 1.1 一组真实数字

实测语料：510 篇 Markdown 笔记。

| 指标 | 数值 |
|---|---|
| 文档数 | 510 篇 |
| 总体积 | 5.0 MB |
| 总字符数 | **3,274,019 字**（约 327 万字） |
| 平均每篇 | 6,419 字 |

按中文默读速度换算（成年人中文默读约 300–500 字/分钟，精读约 100–150 字/分钟）：

| 阅读方式 | 速度 | 读完全部耗时 |
|---|---|---|
| 精读（逐字理解） | 150 字/分钟 | **约 364 小时** ≈ 45 个工作日 |
| 日常默读 | 300 字/分钟 | **约 182 小时** ≈ 23 个工作日 |
| 快速浏览（抓主线） | 500 字/分钟 | **约 109 小时** ≈ 14 个工作日 |

而这些文档是 AI 在**几个月内、以对话的形式**逐篇生成的——单篇的生成时间以**秒**计。

> **这就是问题所在**：
> 生成侧的单位成本已经趋近于零，消费侧的单位成本几乎没变。
> AI 造一卷纸只要几分钟，人读完这卷纸要一两个月。
> 产能瓶颈从「写」转移到了「读」。

### 1.2 三重衰减

更糟的是，"读"本身也不是终点。信息从产生到变成能力，要过三道衰减：

```
生成 3,274,000 字
   ↓ ① 阅读衰减：读不完（时间成本）／读得完但抓不住（工作记忆限制）
   ↓ ② 理解衰减：读到了 ≠ 理解了（缺少结构，无法挂载到已有知识）
   ↓ ③ 记忆衰减：理解了 ≠ 记住了（无提取线索，遗忘曲线）
可用能力 ？ 
```

传统的解法是"让 AI 再总结一遍"。但这只是把①的成本转移，并没有解决②③——一段 2000 字的散文式总结，依然没有结构、无法检索、无法定位出处。

### 1.3 本项目的定位：做「压缩 + 结构化 + 可溯源」

| 层级 | 内容 | 体量 | 阅读成本（300 字/分钟） |
|---|---|---|---|
| L0 原文 | 510 篇笔记 | 327 万字 | 约 182 小时 |
| L1 索引 | 每篇的小标题 + 要点原句 | 约 16 万字 | 约 9 小时 |
| L2 关键词体系 | 10 维度 + 100 父关键词 + 579 子关键词 | **约 6,400 字** | **约 21 分钟** |
| L2+ 带说明版 | 上述 + 每条子关键词的 28 字说明 | 约 2.3 万字 | 约 76 分钟 |

**压缩比约 500:1（L0 → L2）**，且 L2 的每一项都能一键回到 L0 的具体文件。

## 二、认知科学：四条硬约束

### 2.1 工作记忆容量：7±2 与 4±1

| 研究 | 结论 |
|---|---|
| Miller (1956)《神奇的数字 7±2》 | 人能同时保持约 **7 个组块**（chunk） |
| Cowan (2001)、《The Magical Mystery Four》(2010) | 排除复述与组块策略后，核心容量仅 **3~5 个**；多数任务下约 **4 个** |
| 组块与压缩（如 Kolmogorov 复杂度视角的研究） | 组块的本质是**压缩**——一个组块 = 最大压缩编码中的一个单元 |

**为什么会差这么多？** 因为 Miller 的实验里，被试其实在**暗中组块化**。"1-0-6-6" 记成"1066 年"就从 4 个组块变成 1 个。Cowan 控制住这个策略后，得到 4±1。

**对本项目的含义：**

| 设计 | 理论依据 |
|---|---|
| 每个父关键词下挂 **3~7 个子项** | 3~5 是舒适区（Cowan），7 是上限（Miller）；超出就该再分层 |
| 一层最多 **7~10 项**，超过就拆层 | 7±2 是"能同时保持"的天花板，10 是"一眼能扫完"的实用上限 |
| 子关键词压到 **3~12 个字** | 组块要有意义才能被当作"一个单位"；太长就退化成多个组块 |
| 三层而不是一层扁平清单 | 层级本身就是压缩：**100 个平铺的关键词 ≈ 100 个组块（超载）；分 10 组 × 10 个 ≈ 10 + 10（可读）** |

### 2.2 关于"为什么顶级维度是 10 个"

这一条需要诚实说明：**10 个顶级维度略微超出 7±2 的舒适区**。

它能成立，靠三个补偿因素：

1. **带视觉分组**：维度行有独立底色，关键词格有隔行浅底，边界清晰，减少"串行"。
2. **带编号**：`D01-01 … D10-10` 给每个格一个唯一地址，检索时不需要靠位置记忆。
3. **不需要同时保持**：顶层维度是**目录**，不是一个要同时装进工作记忆的组块集合——实际使用时是一次看一个维度，每个维度内 10 项才是真正要同时处理的那一组。

> 这条设计原则值得记住：**当条目数超过 7±2 时，必须提供外部索引（编号 / 颜色 / 分组）来补偿工作记忆。**

### 2.3 认知负荷理论（Sweller, 1988）

工作记忆的负荷分三类：

| 类型 | 来源 | 对学习的作用 |
|---|---|---|
| **内在负荷** | 材料本身的复杂度 | 必要，但过高会造成过载 |
| **外在负荷** | 呈现方式不当（混乱、割裂、冗余） | 有害，纯浪费 |
| **相关负荷** | 用于构建图式的有效努力 | 有益 |

**关键推论**：总负荷有上限，所以**每一分外在不必要的负荷，都是从"真正思考"里扣掉的**。

**对本项目的含义：**

| 做法 | 降低的负荷 |
|---|---|
| 用表格网格而不是散文段落 | 外在负荷（空间一致，不需要在脑中重组） |
| 单元格内「父关键词加粗 + 子项编号换行」 | 外在负荷（视觉层级替代语言层级） |
| 冻结表头、每页重复标题 | 外在负荷（不用记住"这一列是什么"） |
| 保留每条来源文件名 | 外在负荷（不用记住"这条出自哪"） |
| 三种视图各司其职（通读 / 检索 / 溯源） | 外在负荷（不用一张表干所有事） |
| **把 327 万字压到 6,400 字** | 内在负荷（只呈现元素交互性最高的部分） |

反过来，本项目**刻意不做**一件事：不替用户下结论、不写"最重要的三点"。因为那属于**相关负荷**——真正的理解必须由读者自己完成。工具只负责把材料整理到"便于思考"的状态。

### 2.4 图式理论与专家效应

知识以**图式（schema）**的形式存在长时记忆中；图式一旦自动化，就几乎不再占用工作记忆（这正是专家能"一眼看穿"的原因）。

而图式只能**挂载在已有结构上**。面对一团没有结构的材料，大脑只能随机试错。

**对本项目的含义**：一份好的层级表，本质上是**给用户一副骨架**。他可以把新知识挂到已有维度上，而不是每次从零开始组织。这也解释了为什么"视角"如此重要——维度定了，骨架就定了，后续所有知识都往这个骨架长。

### 2.5 双重编码与提取线索

- **双重编码（Paivio）**：同时以语言和视觉形式编码的信息，回忆效果更好。表格的**空间位置**本身就是编码的一部分（"在右上角那一格"）。
- **提取练习（testing effect）**：主动"找出来"比被动"读一遍"记得更牢。**可检索的表格 = 一组现成的提取线索。**
- **间隔重复（spacing effect）**：在遗忘前复习效果最好。因此表格适合**反复扫读**，而不是一次精读。

**对本项目的含义**：多视图设计（矩阵 / 展开 / 明细 / 溯源）实质上是**为不同的复习方式提供不同入口**——扫一眼矩阵是快速复习，筛明细是深度检索。

## 三、结构化思维的成熟方法（我们用了哪些）

### 3.1 金字塔原理（Barbara Minto / 麦肯锡）

核心四条原则：

- **结论先行**：先给中心思想
- **以上统下**：上层必须是下层的概括
- **归类分组**：同组必须属于同一逻辑范畴
- **逻辑递进**：同组内按逻辑顺序排列

以及一个关键数字：**一个论点由 3~7 个论据支持，每个论据又可被 3~7 个二级论据支持**——这与 Miller 的 7±2 完全吻合。

> 本项目的三层结构（维度 → 父关键词 → 子关键词）就是这条规则的直接落地，
> 而 README 的写法（结论先行 → 分点展开）也是在遵守它。

### 3.2 MECE（Mutually Exclusive, Collectively Exhaustive）

**相互独立，完全穷尽**——分类时各部分不重叠、合起来不遗漏。麦肯锡的标准。

常用五种分法：二分法、过程法（按流程）、要素法、公式法、矩阵法（2×2）。

本项目在三个地方强制 MECE：

| 位置 | 怎么保证 |
|---|---|
| 维度划分 | 每个维度有专属的**检索词表**，避免两个维度抢同一批文档 |
| 父关键词 | `05_merge_validate.py` 校验**父关键词集合与 taxonomy 完全一致**（不重不漏） |
| 子关键词 | 校验数量落在 3~7，且每条必须挂靠唯一父关键词 |

> 诚实地说：**完全 MECE 很难做到**。同一篇文档命中多个维度是常态（一篇"采集失败排查"同时属于「爬虫」「排查」「工程」）。
> 我们的处理是：**允许文档重叠，但保证关键词层级不重叠**——前者影响召回，后者影响可读性。

### 3.3 思维导图（Tony Buzan）

要点：中心主题 → 放射状分支 → **每个分支只放一个关键词** → 用颜色和图形建立层级。

本项目借用了它的两条思路：
1. **一线一词**（父关键词控制在 4~10 字，不写成句子）
2. **放射状可展开**（维度 → 关键词 → 子关键词，逐层下钻）

但没有照搬"手绘放射状"的形式——因为终端是 Excel，**网格比放射更适合打印与筛选**。

### 3.4 渐进式摘要（Tiago Forte）

《打造第二大脑》中的五层压缩模型：

| 层 | 内容 |
|---|---|
| L1 | 保存原文 |
| L2 | 加粗关键句 |
| L3 | 高亮最关键的 10~20% |
| L4 | 用自己的话写摘要 |
| L5 | 改写成可复用产出 |

核心理念：**不要在第一次阅读时就追求完美**，每次回顾只推进一层。

**这个项目就是这个模型的一次"工业化"尝试**：

| Forte 的层 | 本项目对应 | 谁来做 |
|---|---|---|
| L1 原文 | `_all_md/`（全量原始笔记） | 机器（脚本下载） |
| L2 加粗 | `03_index_docs.py` 抽取"要点原句" | 机器（正则 + 关键词） |
| L3 高亮 | 03 抽取的"强调词 `**…**`" | 机器 |
| L4 用自己的话总结 | 子代理产出的父/子关键词与说明 | 模型 |
| L5 输出与创造 | 6 视图 Excel | 机器（openpyxl） |

> **与 Forte 的差异**：他把"分层"绑定在**人工回顾**上（"放着不动，分层就白做了"）。
> 我们则把 L2–L4 交给机器一次性跑完，代价是**失去了人工筛选那一步的价值判断**。
> 这是一处明确的取舍：**为"量大"牺牲"精"**。对于确实会再回看的用户，人工在 Excel 上再标一次高亮仍然值得。

### 3.5 其他可借鉴但未采用的方法

| 方法 | 为什么没直接用 |
|---|---|
| **Zettelkasten 卡片盒** | 强调原子化 + 卡片间链接，适合长期知识网络；本项目是"一次性俯瞰"，目标不同 |
| **概念图（Novak）** | 需要标出节点间的**关系词**，信息量更大但制作成本高；适合做深而非做广 |
| **PARA 分类法** | 是"存放位置"的组织方式，不是"内容"的组织方式 |
| **信息架构的卡片分类法** | 需要真实用户参与分类，适合产品设计而非个人知识整理 |

## 四、可以引入的计算方法（技术路线）

> 这一节是**下一步可以做什么**，不是"我们已经做了什么"。
> 当前实现有意保持轻量：**正则 + 关键词匹配 + LLM**，没有引入任何机器学习依赖。

### 4.1 关键词抽取：从统计到语义

| 方法 | 原理 | 特点 |
|---|---|---|
| **TF-IDF** | 词频 × 逆文档频率 | 快（数百篇/秒），但只是"高频词"，语义弱 |
| **RAKE** | 停用词切分候选短语 + 词度/词频打分 | 适合英文；中文因停用词难穷举，效果受限 |
| **TextRank** | 词共现图 + PageRank | 无监督、语言无关性好 |
| **YAKE** | 多特征启发式（位置、大小写、词形相似） | 同类中较先进；无监督、单文档 |
| **KeyBERT** | 用句向量模型比较候选词与文档的余弦相似度 | 语义质量高（有评测显示 F1 明显优于 TF-IDF/RAKE），但慢得多 |
| **LLM 直接生成** | 让模型读文档产出关键词 | 可读性最好、能带上下文；成本与不可复现性最高 |

**评测参考**（第三方基准，非本项目实测）：KeyBERT 类方法在语义一致性与 F1 上明显优于统计方法，但吞吐量低 1~2 个数量级；TF-IDF 快但语义质量弱。

> **本项目当前用的是 LLM 路线**（父关键词由模型命名），辅以脚本做**机械抽取**（小标题、加粗词）作为证据。
> 这是刻意的：**可读性优先于可复现性**——这张表是给人读的，不是给机器评估的。

### 4.2 主题建模与层次聚类

| 方法 | 原理 | 与本项目的关系 |
|---|---|---|
| **LDA** | 词袋 + 概率生成模型 | 经典但易产出不可读的主题词堆 |
| **NMF** | 矩阵分解 | 比 LDA 更稳定，仍依赖词袋 |
| **BERTopic** | 句向量嵌入 → UMAP 降维 → HDBSCAN 聚类 → c-TF-IDF 生成主题表示 | **最值得引入**，见下 |
| **凝聚层次聚类** | 自底向上合并，产出**树状图** | 天然对应"分层"，但需人工确认切几层 |

**BERTopic 为什么值得关注**：它的流程天然贴合本项目要做的事——
把"语义相近的文档聚成主题"，而且聚类算法可换成 **Agglomerative Clustering 直接产出主题层级**。

**如果引入，能改善什么**：目前维度划分靠**人工定义检索词表**，本质是关键词匹配，
会有两个问题：① 检索词想不到就漏召；② 同义不同词的文档聚不到一起。
换成嵌入聚类后，**召回率与语义一致性都会提升**，代价是结果不可预测、需要人工复核。

### 4.3 语义去重

当前实现只做了**文件名/内容层面的去重**（发现 510 篇里大量是同一内容的不同时间戳副本）。
更强的做法：

| 方法 | 用途 |
|---|---|
| 句向量余弦相似度 | 判定两篇是否语义重复（可设阈值，如 0.9） |
| **MinHash + LSH** | 大规模近似去重，速度快、可扩展 |
| SimHash | 近似重复检测，适合短文本 |

**收益**：现在的"被引用文档 121/510"里，有相当一部分冗余是副本造成的。语义去重后能给出更真实的覆盖度。

### 4.4 质量评估指标

目前只有**结构性校验**（不重不漏、来源存在）。可以再加**质量性指标**：

| 指标 | 定义 | 用途 |
|---|---|---|
| **覆盖率** | 被关键词引用到的文档数 / 总文档数 | 太低说明视角太窄或检索词不足 |
| **饱和度** | 每维度命中文档数 / 该维度关键词数 | 判断维度是否过细 |
| **层级平衡度** | 各维度子项数的方差 / 标准差 | 差异过大说明维度划分不均 |
| **来源集中度** | 单个文档被引次数占比 | 某篇被引 40 次 → 可能是"万能文档"，也可能是它在灌水 |
| **可辨识度** | 关键词之间的字面重复度 | 检测"同义不同写"的冗余条目 |

> 本项目的实测数据正好可以拿来当基线：121/510 ≈ **23.7% 覆盖率**；
> 单篇最高被引 39 次（`044_版本更新汇总_2026年10月.md`）——这提示"月度汇总"类文档天然是信息枢纽。

### 4.5 人机分工的边界（这是最需要想清楚的一条）

| 判断 | 依据 |
|---|---|
| 机器**擅长**：召回、去重、聚类、统计、格式渲染 | 确定性强，可校验，成本几乎为零 |
| 机器**不擅长**：命名、取舍、判断"什么重要" | 需要价值判断，且不同人答案不同 |
| 人的**不可替代处**：选视角、定名字、决定留什么 | 这正是"相关负荷"所在，外包掉就等于放弃了理解 |

**本项目当前的分工线**：机器做到"结构化 + 可溯源"，人在 Excel 上做"标注 + 取舍"。

## 五、理论 → 实现的映射表

| 理论 / 方法 | 在本项目中的落点 |
|---|---|
| Miller 7±2 / Cowan 4±1 | 每层 3~7 子项；可控宽度；超限即分层 |
| 组块化与压缩 | 三层结构本身即压缩；327 万字 → 6,400 字 |
| 认知负荷理论 | 表格替代散文；视觉层级；冻结表头；多视图分工 |
| 图式理论 | 维度 = 骨架；先定视角再填内容 |
| 双重编码 / 提取线索 | 网格布局 + 编号 + 颜色分带；可筛选的明细表 |
| 金字塔原理 | 三层结构；父关键词下 3~7 个子项；结论先行的文档写法 |
| MECE | 校验"父关键词不重不漏"；维度检索词互斥 |
| 思维导图 | 一线一词；逐层下钻 |
| 渐进式摘要 | L1 原文 / L2 要点句 / L3 强调词 / L4 关键词 / L5 Excel |
| 文档溯源索引 | 对抗 LLM 幻觉的机械校验（非理论，是工程必需） |
| 语义聚类（待引入） | 用嵌入 + 层次聚类替代人工检索词表 |
| 语义去重（待引入） | 提升覆盖率统计的真实性 |

## 六、已知不足与改进路线

| # | 不足 | 方向 |
|---|---|---|
| 1 | 维度靠人工检索词表，召回不全 | 引入 BERTopic / 层次聚类做候选维度，人工复核 |
| 2 | 只做文件名级去重 | 加 MinHash+LSH 或句向量语义去重 |
| 3 | 无质量指标，只有结构校验 | 加覆盖率 / 层级平衡度 / 来源集中度 |
| 4 | 一次性生成，无增量 | 支持"新增笔记 → 只重跑受影响维度" |
| 5 | 丢失了 Forte 模型中"人工筛选"的价值 | 在 Excel 上开放标注位，允许用户二次高亮，形成 L4.5 |
| 6 | 三层即止，没有跨维度的**关联** | 引入概念图的"关系词"，标注维度之间的交叉（如"爬虫"与"部署"共享"会话"概念） |
| 7 | 未验证可读性收益 | 做一次 A/B：直接读索引包 vs 读关键词表，测量回顾任务的完成时间与准确率 |
