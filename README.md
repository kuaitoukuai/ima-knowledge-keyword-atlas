# ima-knowledge-keyword-atlas

> 把散落的上千篇知识库笔记，自动炼成一套**可读、可查、可打印、每条都能追到原文**的分层关键词体系。

一个 **WorkBuddy / Claude Code 风格的 Skill（技能包）**：从 IMA（艾玛）知识库批量拉取 Markdown 笔记，
逐层提炼关键词与子关键词，最后渲染成多视图 Excel。

**实测规模**：510 篇笔记 → 10 个技能维度 × 10 个父关键词 → **579 个子关键词**，逐条溯源到 **121 篇原始文档**。

## 它解决什么问题

用 AI 记笔记的人普遍会遇到同一个尴尬：**笔记越写越多，却再也读不完第二遍**。

- 想回顾「我这半年到底积累了哪些本事」，面对的是几百个文件名
- 想让笔记变成可复用的知识，却发现它只是「当时的对话记录」
- 整理一次很爽，但下次又堆积如山，没有可重复的方法

这个项目给出一套**可重复执行的流水线**：把「批量文档」压成「分层关键词」，再落成一张能打印、能检索、能追源的 Excel。

它不是「让模型读一遍然后写个总结」——那种做法的问题是**无法验证**。这里每个关键词都必须能指回具体文件，并且有脚本硬校验。

## 一组数字：瓶颈已经转移

| 指标 | 数值 |
|---|---|
| 实测语料 | 510 篇笔记 / 5.0 MB / **327 万字** |
| 人精读一遍（150 字/分钟） | **约 364 小时 ≈ 45 个工作日** |
| 人日常默读一遍（300 字/分钟） | **约 182 小时 ≈ 23 个工作日** |
| 这 510 篇由 AI 生成 | 跨度几个月，**单篇以秒计** |

生成侧的成本已经趋近于零，**消费侧几乎没变**。AI 造一卷纸只要几分钟，人读完要一两个月。

再往下还有两道衰减：读到了 ≠ 理解了（缺结构无法挂载），理解了 ≠ 记住了（无提取线索）。

本项目的答案是**压缩 + 结构化 + 可溯源**：

| 层级 | 体量 | 阅读成本 |
|---|---|---|
| L0 原文 | 327 万字 | 约 182 小时 |
| L1 结构索引（小标题 + 要点原句） | 约 16 万字 | 约 9 小时 |
| **L2 关键词体系** | **约 6,400 字** | **约 21 分钟** |

**压缩比约 500:1**，且 L2 的每一项都能一键回到 L0 的具体文件。

## 理论依据

这套流水线不是「试了觉得还行」，而是对应着既有的研究结论。完整论述见
**[docs/理论依据与认知设计.md](docs/理论依据与认知设计.md)**，这里给一张速查表：

| 理论 / 方法 | 关键结论 | 在本项目中的落点 |
|---|---|---|
| **Miller (1956) 7±2** | 工作记忆约容纳 7 个组块 | 每层最多 7~10 项，超限即分层 |
| **Cowan (2001/2010) 4±1** | 排除组块策略后仅 3~5 个 | 每个父关键词下挂 **3~7 个子项** |
| **组块化与压缩** | 组块的本质是压缩 | 三层结构本身就是压缩：327 万字 → 6,400 字 |
| **认知负荷理论 (Sweller 1988)** | 外在负荷每多一分，思考就少一分 | 表格替代散文、冻结表头、多视图分工 |
| **图式理论** | 新知识必须挂载到已有结构上 | 先定「视角」= 先定骨架 |
| **双重编码 / 提取线索** | 空间位置与检索动作强化记忆 | 网格 + 编号 + 颜色分带 + 可筛选明细 |
| **金字塔原理 (Minto)** | 论点由 3~7 个论据支持，逐层展开 | 维度 → 父关键词 → 子关键词 |
| **MECE** | 互斥、穷尽 | 脚本校验「父关键词不重不漏」 |
| **思维导图 (Buzan)** | 一线一词，逐层下钻 | 父关键词 4~10 字，不写成句子 |
| **渐进式摘要 (Forte)** | 五层压缩，逐层提炼 | L1 原文→L2 要点句→L3 强调词→L4 关键词→L5 Excel |

> **一处诚实的取舍**：Forte 的渐进式摘要依赖**人工多次回顾**，我们把它交给了机器一次性跑完。
> 代价是失去了人工筛选那一步的价值判断——**为「量大」牺牲了「精」**。
> 所以 Excel 里刻意留了空间让你自己再标一次高亮。

文档还讨论了**尚未采用但值得引入**的计算方法：BERTopic 层次聚类（替代人工检索词表）、
MinHash+LSH 语义去重、覆盖率/层级平衡度等质量指标，以及最难的一条——**人机分工的边界**。

## 核心特性

| 特性 | 说明 |
|---|---|
| **分层关键词体系** | 维度 → 父关键词 → 子关键词，三层结构，层层可展开 |
| **逐条可溯源** | 每条子关键词都带 `src`（来源 md 文件名），溯源表列出**全部**源文档及引用状态 |
| **硬校验闸门** | 建表前脚本强制校验：父关键词不重不漏、子项数在区间、**每条来源文件真实存在** |
| **6 视图 Excel** | 矩阵总览 / 含子关键词总览 / 关键词展开 / 子关键词明细 / 文档溯源索引 / 维度统计 |
| **可打印** | A4 横向、冻结表头、每页重复标题、按内容自动计算行高 |
| **断点续传** | 下载、索引、出表均可重跑，不重复劳动 |
| **纯本地** | 只有调用 IMA 官方接口取数据；关键词提炼与 Excel 生成全在本机完成 |

## 工作流总览

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ A 拉取   │ → │ B 建索引 │ → │ C 聚类   │ → │ D 细读   │ → │ E 校验   │ → │ F 出表   │
│ 清单+正文│   │ +定维度  │   │ 出摘要   │   │ 展开子词 │   │ 硬闸门   │   │ 6 视图   │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
   01 + 02        03 + 人工       04          并行子代理        05            06
```

关键点：**Phase E 是质量闸门，不可跳过**。跳过它，幻觉来源文件名会一路带进交付物。

## 快速开始

### 前置条件

| 依赖 | 说明 |
|---|---|
| IMA 凭证 | 在 <https://ima.qq.com/agent-interface> 获取 Client ID 与 API Key，存到 `~/.config/ima/client_id` 与 `~/.config/ima/api_key` |
| `ima_api.cjs` | 来自 IMA 官方 skill，默认从 `~/.workbuddy/skills/ima-skills` 查找，可用环境变量 `IMA_SKILL_DIR` 覆盖 |
| Node.js | 在 `PATH` 中（调用接口用） |
| Python 3.8+ | 建索引与生成 Excel（自动安装 `openpyxl>=3.1`） |

### 安装为 Skill

```bash
git clone https://github.com/kuaitoukuai/ima-knowledge-keyword-atlas.git \
  ~/.workbuddy/skills/ima-knowledge-keyword-atlas
```

之后在 WorkBuddy 里说「把这个知识库整理成关键词体系」即可触发。

### 或者直接用命令行跑

```bash
SD="$(pwd)/scripts"
WD="$HOME/kb-atlas"          # 工作目录，所有中间产物落在这里
mkdir -p "$WD"

bash    "$SD/01_list_kb.sh"    "我的知识库"        "$WD/list.jsonl"
bash    "$SD/02_fetch_docs.sh" "$WD/list.jsonl"    "$WD/md" 3

python3 "$SD/03_index_docs.py" --src "$WD/md" --out "$WD/index" --per-pack 40
#   ↑ 读 $WD/index/pack_*.md 通读全量，产出 $WD/taxonomy.json（维度与关键词由你定）

python3 "$SD/04_cluster_digest.py" --index "$WD/index/index.json" \
        --taxonomy "$WD/taxonomy.json" --out "$WD/digest" --top 32
#   ↑ 此处可并行派子代理做细读，产出 $WD/expand/*.json
#     提示词模板见 references/subagent-prompt.md

python3 "$SD/05_merge_validate.py" --expand "$WD/expand" \
        --taxonomy "$WD/taxonomy.json" --md "$WD/md" --out "$WD/merged.json"

python3 "$SD/06_build_workbook.py" --merged "$WD/merged.json" --md "$WD/md" \
        --out "$WD/关键词体系.xlsx" --title "我的技术关键词体系"
```

## 六阶段详解

| 阶段 | 脚本 | 做什么 | 关键约束 |
|---|---|---|---|
| **A 拉取** | `01_list_kb.sh` + `02_fetch_docs.sh` | 翻页拉全量清单，再下载每篇正文 | 下载**并发 ≤3**（并发 8 时实测 510 篇有 242 篇被限流） |
| **B 建索引 + 定维度** | `03_index_docs.py` | 每篇压成「标题/日期/小标题/要点原句/强调词」，并生成可直接读进上下文的索引包 | **先跟用户确认视角**，这是最容易返工的一步 |
| **C 聚类** | `04_cluster_digest.py` | 按维度聚出「完整摘要 + 紧凑摘要」 | 命中篇数过少会告警（通常是检索词太窄） |
| **D 细读** | 并行子代理 | 每 1~2 个维度一个代理，把父关键词展开成 3~7 个子关键词 | 子关键词写成「踩的坑 / 采取的做法」 |
| **E 校验** | `05_merge_validate.py` | 父关键词集合一致、子项数在区间、**每条 src 真实存在** | 不过就报错退出，不带错误建表 |
| **F 出表** | `06_build_workbook.py` | 渲染 6 视图 Excel | 静态速览表不写 Excel 公式（详见下文） |

细节见 [`references/workflow.md`](references/workflow.md)，
并行子代理提示词模板见 [`references/subagent-prompt.md`](references/subagent-prompt.md)。

## 生成的 Excel 长什么样

一次产出 6 个工作表：

| 视图 | 结构 | 用途 | 打印 |
|---|---|---|---|
| ① 总览矩阵 | 维度 × 关键词网格，带 `D01-01` 编号 | 一页纸目录 | A4 横向，一页装下 |
| ①B 总览（含子关键词） | 同网格，每格父关键词下直接列出子关键词（父词加粗） | 一屏纵览全貌 | 纵向续页 |
| ② 关键词展开 | 1 个父关键词 = 1 行，子关键词格内换行 + 来源 | 逐条通读 | — |
| ③ 子关键词明细 | 1 个子关键词 = 1 行，含说明、来源 md、日期，带筛选 | 检索 / 当字典 | 纵向续页 |
| ④ 文档溯源索引 | **全部**源文档逐篇列出，标注被引用与否 | 反向倒查出处 | 纵向续页 |
| ⑤ 维度统计 | 各维度规模 + 柱状图 | 看结构分布 | — |

## 设计取舍（为什么这么做）

这部分是这个项目真正的「思想」，也是它和「让模型写个总结」的根本差别。

### 1. 先结构化，再校验，最后才出表

中间产物（`index.json` / 摘要 / 展开 JSON）**必须落盘**。原因有两个：

- 可**校验**：只有结构化数据才能写脚本检查「来源文件是否真实存在」
- 可**重跑**：改关键词只需重跑 D~F，不用重新抓一遍文档

### 2. 两级阅读策略：摘要优先，原文下钻

把每篇文档压成「小标题 + 问题/原因/解决类原句 + 强调词」，
再按维度取相关度前 N 篇做紧凑摘要。子代理先读摘要，证据不足时再 grep 原文。

> 只读摘要会浮于表面，只读原文会爆上下文。两级推进最省。

### 3. 每条结论都必须能指回原文

子关键词的 `src` 必须是**磁盘上真实存在的文件名**，并由脚本逐个校验。

这是 LLM 最容易出错的地方——它会流畅地编出一个「看起来非常合理」的文件名。
所以校验不能靠模型自查，必须靠文件系统。

### 4. 确定性的事交给脚本，判断的事交给模型

| 交给脚本 | 交给模型 |
|---|---|
| 翻页、下载、重试、限流退避 | 该分哪几个维度 |
| 抽取标题/小标题/要点原句 | 父关键词怎么命名 |
| 聚类、统计、校验文件存在性 | 子关键词怎么概括 |
| 生成 Excel、行高计算、打印设置 | 取舍哪些内容值得留下 |

### 5. 如实告知，不假装

- 一页纸放不下就续页，**并把页数告诉用户**，不强行 `fitToHeight=1` 把字号压到 5pt
- 没有 LibreOffice / `formulas` 引擎时，不写 Excel 公式（预览会显示空白），直接写计算结果
- 目标文件被占用写不进去时，另存新文件并说明，不静默失败

## 常见问题

**Q：为什么不直接让模型读完写总结？**
因为无法验证。总结里的每条结论都无法溯源，也无法判断模型有没有编。这里每个关键词都要能指回原文，且有脚本把关。

**Q：文档太多读不完怎么办？**
这正是 `03_index_docs.py` 的作用：把每篇压成几十行结构索引，按 40 篇一包，
可以整包读进上下文而不爆窗口。全量 510 篇生成的索引包总计不到 2 MB。

**Q：为什么下载并发要限制在 3？**
实测并发 8 时 510 篇里有 242 篇被服务端限流（接口返回空 URL）。
并发 3 + 每篇重试 4 次可以 100% 成功。脚本可以反复重跑补齐，不会重复劳动。

**Q：一定要用 IMA 知识库吗？**
不必。只要有一批 Markdown 文件，就能从 Phase B 开始用（把 `--src` 指向你的 md 目录）。

**Q：能不能改成 8×6 或者别的规格？**
可以，规格由 `taxonomy.json` 决定，脚本本身不写死维度数与关键词数。

**Q：这个项目会读取或上传我的笔记内容吗？**
不会。笔记只从 IMA 官方接口拉到本机处理，关键词提炼与 Excel 生成全在本地完成，
仓库里不包含任何用户数据。
